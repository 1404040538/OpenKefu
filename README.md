## 为什么选 OpenKefu

- **一套系统管多平台店铺**：拼多多 + 淘宝（千牛）的店加进同一个管理台，告别多后台来回切换
- **AI 客服不下班**：深夜、饭点、休假不漏接，答不上来提醒你接手
- **答得准、不瞎编**：先查顾客的真实订单和商品再回答（拼多多），查不到就如实说
- **挂上去就不用管**：掉线自动重连、重启自动恢复、漏掉的消息自动补回
- **数据自己掌握**：自建自管，店铺凭据加密保存，聊天与售后记录都在你自己的数据库里

## 先讲一个晚上的故事

凌晨 0 点 47 分，你的店早就打烊，客服也下了班。拼多多和淘宝两家店铺都挂在 OpenKefu 上，安静地等着顾客上门。

一位顾客在拼多多戳了戳你的店铺（以下为功能演示的示例对话）：

> **顾客**：在吗？这个保温杯 500ml 的还有货吗？
>
> **OpenKefu**：您好，欢迎光临～这是您设置的开场白，新顾客一来就自动送上。回答则是 AI 先查了商品的价格、规格和库存，再照着你的店规说出来的。

> **顾客**：我上周买的那单怎么还没发货？
>
> **OpenKefu**：帮您看了下，您 10 月 2 日拍的订单目前是「待发货」状态，已经帮您记录加急备注啦。

顾客问到订单，AI 会先去店铺后台查**这位顾客的真实订单**——待付款、待发货、已发货、退款中，看得清清楚楚；查不到就如实说查不到，绝不编一个物流单号糊弄人。

> **顾客**：不行，太慢了，我要退货。
>
> **OpenKefu**：好的，方便提供一下订单号和退货原因吗？我帮您登记。

顾客聊到退货、换货、仅退款、改地址，AI 会像老客服一样把订单号、原因追问齐，核对订单是不是真在你店里下的，再自动登记成一条售后记录——不用你翻聊天记录抄笔记。

> **顾客**：算了，直接转人工。
>
> **OpenKefu**：好的，正在为您转接人工客服。

按你提前排好的顺序，会话自动转给店里的真人客服，一位转不上自动试下一位；实在转不成，管理台立刻标红、响铃提醒。转人工之后，AI 自动闭嘴，绝不多插一句嘴。

同一晚，你淘宝店里也有顾客发来一张截图问「和图片色差大吗」——图片原样显示在聊天窗口里，不会变成一串乱码；AI 照常接待，接不住的部分安静地排进「待人工」队列，等你早上来处理。

第二天早上你打开 OpenKefu：昨晚的退货申请已经躺在「退换记录」里，点一下导出 Excel 交给仓库处理；如果夜里恰好断过网，系统也早已把漏掉的顾客消息悄悄补了回来。**这一整晚，你没守过一分钟屏幕。**

**这就是 OpenKefu 想做的事：让每一位店主，都请得起一位不下班、不瞎编、懂你店规的 AI 客服。**

## OpenKefu 是什么

OpenKefu 是一个开源自建的多平台店铺 AI 客服管理台：在你自己的服务器上跑一个网页，把**拼多多**和**淘宝（千牛）**的店铺都挂上去，顾客咨询实时汇总到同一个聊天页；AI 按你上传的资料 7×24 小时自动接待，答不上来响铃提醒你接手，或按你排好的顺序自动转给指定客服；顾客聊到退换货，还会自动记账、一键导出 Excel。数据全程握在你自己手里。

## 一个后台，管住两个平台的店

不用在拼多多商家后台和千牛工作台之间来回切换。店铺都挂进 OpenKefu，两个平台的顾客咨询汇进同一个聊天页——像用一个微信，同时回两个平台的客人。

**接店很快：**

- **拼多多**：网页上出个二维码，用手机拼多多商家版扫一下、确认，店铺就挂上了；碰到平台故意刁难的验证码，系统还会自动换个环境重试。不想扫码就填账号密码，需要短信验证时验证码直接发到你手机，填一次就登录成功。
- **淘宝（千牛）**：手机淘宝扫一下码即可接入，约 30 秒，页面实时显示「等扫码 → 已扫码 → 登录成功」的进度；就算消息被手机千牛「抢走」了，系统每 12 秒还会主动巡查一遍兜底，不漏消息。

## AI 客服：全天在岗，答得准

顾客一来消息，系统按下面的顺序作答，又快又稳：

1. **标准问答秒回**：预设「问题 + 答案」（还能配图片），顾客问到就直接发，零等待
2. **常用话术**：打招呼、「什么时候发货」「能退吗」这类高频话，按预设话术立刻回复
3. **相似问题复用**：和之前问过的高度相似时，直接复用那条高质量回答，更快也更省
4. **AI 现场回答**：结合这位顾客的聊天记录、你的店规和知识库资料，写一条得体的回复

- **听得懂**：自动分辨问商品、催发货、改地址、退换货、快递异常、投诉等 15 类常见诉求，对症回答
- **不瞎编**：查不到的订单、物流、退款一律如实说查不到，绝不编造订单号和金额（拼多多店铺回答订单、商品问题前，会先查这位顾客的真实订单和商品价格、规格、库存，拿真数据说话）
- **记性好**：顾客接着上一句追问「那这个呢」，也接得上话，不答非所问
- **不刷屏**（拼多多）：顾客一口气连发几条，AI 稍等片刻合并成一条完整回复，不连珠炮吓到人
- **有据可查**：AI 把每句话理解成什么诉求、回了什么，全程留档，随时回看核查
- **开关随心**：全店一键开关、单个顾客单独关掉、「强制 AI 回复」模式，全由你说了算

## 教会 AI 懂你的店

- 商品说明、发货规则、售后政策等 Word / Excel / PDF 文件直接上传，AI 自动「读懂」
- 高频问题设好标准答案（还能配图），顾客一问到就用你定的说法，又快又不出错
- 用「注意事项」给 AI 立店规——比如不许承诺具体到货时间——AI 每次回复前都对照自查
- 知识库分店铺绑定，A 店的答案绝不会跑到 B 店去

## 该人工时，绝不硬撑

- 顾客点名「转人工」「投诉」，或 AI 没把握时，自动按你排好的顺序转给真人客服，一位转不上自动试下一位（拼多多）；千牛会话则自动排进待人工队列，响铃提醒
- 需要真人处理的会话自动排到最前面，声音提醒＋待处理计数，顶栏实时可见
- 转人工后 AI 自动停止插话（拼多多）；聊天中还能一键把会话转给指定同事并附一句留言

## 售后自动记账

- 顾客提到退货、换货、仅退款、改地址、拦截快递，自动登记一条售后记录；同一顾客同一订单不重复记
- 拼多多店铺的 AI 还会礼貌追问订单号、原因、新地址，并核对订单是不是真在你店里下的
- 台账支持手工补录和修改，按店铺、类型、关键词、时间范围筛选，一键导出 Excel，对账、交接都省事

## 多人协作，权限清晰

- 给每位客服开独立账号，只授权他负责的那几家店，谁家的消息就推到谁的工作台；管理员一个账号看全部，停用账号、重置密码立刻生效
- 聊天时右侧直接显示这位顾客浏览过哪些商品、下过什么单、订单什么状态；淘宝会话还能看到顾客是从哪个商品进店咨询的（带标题和主图），回话心里有底

## 挂上去，就不用管了

这套系统专为长期挂着跑而设计：

- **断了会自己好**：网络一抖自动重连、越试越稳，把店铺悄悄挂回在线；服务器重启或程序退出后，之前在线的店铺会被自动一家家重新拉上线
- **每天主动保养**：每天固定时间换一条新连接，而且是先接通新的、确认没问题才断开旧的——换的过程中顾客消息一条都不丢
- **绝不重复回复**：每家店同一时间只允许一套系统在接待，不会出现两个机器人抢着答话；也因为有这道锁，店多了可以多开几台服务器分担
- **假在线自动纠偏**：系统每分钟自动体检，发现面板写着在线、实际连接早已断掉的店铺，立刻纠正状态并提示你一键重上
- **数据自己瘦身**：运行日志留 30 天、回复记录留 90 天、过期二维码留 7 天，到期自动清理，挂一年也不会被数据拖慢
- **安全有底**：店铺账号密码加密后才存进数据库，日志里密码、验证码自动打码；密码连错几次临时锁定、短信验证码限频、初始化管理员只允许服务器本机操作

## 快速开始

环境要求：Python 3.11+、Node.js 18+、MySQL 8.x（Redis 可选），以及一个大模型 API Key（默认对接 DeepSeek，也支持任何 OpenAI 兼容接口）。

**第一步 · 安装**

```bash
git clone https://github.com/1404040538/OpenKefu.git
cd OpenKefu
pip install -r requirements.txt
cd web && npm install && npm run build && cd ..
```

**第二步 · 配置**

```bash
cp config.example.json config.local.json
```

编辑 `config.local.json`：填好数据库密码和大模型 API Key，再把 `jwt_secret`、`runtime.command_secret`、`security.data_encryption_key` 换成三个不同的随机长字符串——缺少任何一个都会拒绝启动。店铺的登录凭据就是用这些密钥加密保存的，请妥善保管。

**第三步 · 启动**

```bash
python run_web.py --prod --role both
```

浏览器打开 `http://127.0.0.1:8000`，首次访问会引导你创建管理员账号（仅限服务器本机操作）。

**第四步 · 扫码接店**

1. 「店铺管理」→ 新建店铺 → 登入
2. 拼多多店铺用手机**商家版** App 扫码（也支持账号密码登录，短信验证码在页面里就能填）；淘宝店铺用手机淘宝扫码
3. 登录成功自动上线；到「知识库」上传资料、设好标准问答，回来打开店铺的 AI 开关——AI 客服正式上岗

## 部署与贡献

本机体验单进程即可；店多了或要正式上线时，项目自带完整部署方案——全程加密访问、多台服务器分担负载、数据库安全加固清单，见 [deploy/README.md](deploy/README.md)。服务重启后，之前在线的店铺会自动恢复上线，不用挨个重新登录。
